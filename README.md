### 2. 🔄 複数社を跨ぐシームレスな相互直通運転 & 自動追尾ハンドオーバー
- **最大5社・5路線を跨ぐ完全貫通直通ネットワーク（進行方向前方指向連鎖 / Forward-Pointing Chain）**:
  - **上野東京ライン ↔ 東海道線 ↔ 宇都宮線・高崎線・常磐線快速（首都圏南北貫通幹線）**:
    - 沼津・熱海・小田原 ↔ 東京 ↔ 上野 ↔ 大宮 ↔ 宇都宮・黒磯 / 高崎・前橋（両毛線直通）/ 取手・水戸・いわき。東京〜上野間の連絡線を介して都心を貫通する大動脈ネットワークをリアルタイム追尾。
  - **湘南新宿ライン ↔ 東海道線・横須賀線 ↔ 高崎線・宇都宮線（広域縦断ネットワーク）**:
    - 小田原・逗子 ↔ 大船 ↔ 横浜 ↔ 新宿 ↔ 池袋 ↔ 大宮 ↔ 高崎・前橋 / 宇都宮。山手貨物線・品鶴線経由の南北直通系統を完全追尾。
  - **横須賀線 ↔ 総武快速線（東京地下トンネル直通）**:
    - 久里浜・横須賀・逗子・大船・横浜 ↔ 東京 ↔ 錦糸町・市川・船橋・津田沼・千葉・成田空港・君津・上総一ノ宮。東京駅地下ホームを介した直通運転。
  - **東海道線 ↔ 伊東線 ↔ 東海道線（静岡地区: 熱海〜沼津）**:
    - 東京方面 ↔ 熱海 ↔ 伊東（特急踊り子・普通）、東京方面 ↔ 熱海 ↔ 三島・沼津（JR東日本・JR東海の越境直通）。
  - **高崎線 ↔ 両毛線 ↔ 上越線**:
    - 高崎駅・新前橋駅を介した前橋方面（両毛線直通）および渋川・水上・宮内方面（上越線）への相互直通・広域接続。
  - **相鉄 ↔ 東急 ↔ 地下鉄 ↔ 東武 / 西武 広域直通（海老名〜小川町・飯能）**:
    - 相鉄本線・いずみ野線（海老名・湘南台）↔ 相鉄新横浜線 ↔ 東急新横浜線 ↔ 東急東横線 ↔ 東京メトロ副都心線 ↔ 東武東上線（森林公園・小川町）/ 西武池袋線（飯能・小手指）。
    - 5社局を直通する長大ルートにおいて、各社の境界駅（西谷、新横浜、日吉、渋谷、和光市/小竹向原）を跨いでも列車が消失することなくシームレスに追尾。
  - **東急東横線 ↔ みなとみらい線 ↔ 東京メトロ副都心線 ↔ 東武東上線 / 西武池袋線（5社相互直通）**:
    - 元町・中華街〜横浜〜渋谷〜池袋〜森林公園・飯能を結ぶFライナーやS-TRAINの完全貫通追尾。
  - **相鉄・JR直通線 ↔ 相鉄新横浜線・本線 ↔ JR埼京線・川越線**:
    - 海老名〜西谷〜羽沢横浜国大〜武蔵小杉〜大崎〜新宿〜大宮〜川越。境界駅を跨いでも本来の最終目的地を透過的に案内。
  - **小田急小田原線 ↔ 江ノ島線 ↔ 多摩線**:
    - 相模大野駅・新百合ヶ丘駅を介した快速急行・急行・各駅停車等の相互直通運転。
  - **川越線 ↔ 埼京線 ↔ りんかい線**:
    - 川越〜大宮〜新宿〜大崎〜新木場を透過的に維持・案内。
  - **西武池袋線 ↔ 西武有楽町線 ↔ 東京メトロ有楽町線・副都心線**:
    - S-TRAIN（豊洲・元町中華街 ↔ 所沢・西武秩父）を含む全区間を追尾。
  - **東京メトロ千代田線 ↔ JR常磐線（各駅停車）**:
    - 代々木上原〜大手町〜北千住〜綾瀬〜松戸〜柏〜我孫子〜取手の相互直通運転。
  - **西武池袋線・西武秩父線 ↔ 秩父鉄道秩父本線**:
    - 御花畑駅・西武秩父駅の短絡連絡線を介した三峰口・長瀞方面直通運転。
  - **中央線 ↔ 青梅線 ↔ 五日市線**:
    - 立川駅・拝島駅を介した青梅特快・快速・各駅停車の相互直通運転。
  - **八高線 ↔ 川越線**:
    - 高麗川駅での相互直通運転（八王子〜高麗川〜川越）。
  - **中央線 ↔ 中央本線**:
    - 高尾駅を跨ぐ特急（あずさ・かいじ・富士回遊等）および普通列車の相互直通。
- **全区間始発駅（customOrigin）＆終着駅（End-to-End）の動的解決**:
  - 直通先路線に移っても本来の始発駅情報（例: 「海老名発 小川町行き」）を失わず、正確なトリップ全体像を透過表示。
- **自動ハンドオーバー & 路線自動追加**:
  - 追尾中の列車が路線境界を越えて別路線のトリップに移行した際、自動的にカメラ追従を継承。
  - 遷移先路線が非選択状態であっても自動的に選択路線リストに追加し、見失うことなく追尾を継続。

### 4. ⚡ オンデマンド動的時刻表ローディング & 高性能アーキテクチャ
- **オンデマンド動的時刻表ローディング (Dynamic Timetable Loading)**:
  - 初期バンドルサイズを従来の **66MBから1.4MBへ97.8%削減**。
  - 選択中の路線および直通先路線の時刻表JSONのみを動的にストリーミング取得し、初期ロード時間の極小化と省メモリ化を実現。
- **モジュラーカスタムフック & Context レイヤー分離**:
  - `TrainMap` の肥大化を解消し、6つの単一責務カスタムフック（`useLeafletMap`, `useTrackPolylines`, `useStationMarkers`, `useTrainMarkers`, `useMapCamera`, `useGeolocation`）に分離。
  - 状態管理を `SimulationContext`, `SelectionContext`, `FilterContext`, `UIContext` に階層化し、コンポーネント再レンダリングを局所化。
- **モバイルパフォーマンス最適化（白化・フリーズ解消 & 60fps安定化）**:
  - **GPUレイヤー合成負荷の極小化**: マーカーの重い `filter: drop-shadow` を廃止し軽量な CSS `shadow-md` に置き換え。選択時のみ `train-pulse`（`animate-ping`）を DOM 生成することで、非選択列車約390台による常時 GPU アニメーション負荷を全廃し、モバイル（iOS Safari / WebKit等）での VRAM 枯渇による白画面クラッシュ（White Screen of Death）を完全解消。
  - **タイル白抜け＆リサイズ暴走防止**: Leaflet の `fadeAnimation: false` を設定しズーム・パン中のタイル透明化を遮断。`ResizeObserver` に 150ms デバウンスを導入し、アニメーション中の連続リサイズによるフリーズを防止。
  - **駅マーカー（778駅）のキャッシュ＆差分更新**: 駅選択時の `clearLayers()`（全破棄・全再生成）を廃止し、選択駅要素の CSS クラス差分のみを即座に更新。
  - **再レンダリングのスロットリング**: `SimulationContext` において秒数が変化していない描画フレームの更新を完全スキップし、毎秒数十回の無駄な全ツリー再計算を抑制。
  - **CSS Containment**: マーカー要素に `contain: layout style; will-change: transform;` を指定し、リフロー影響範囲を局所化。

## 🚀 ローカルでの動かし方

### 前提条件
- [Node.js](https://nodejs.org/) (v20.x 以上推奨)
- npm (v10.x 以上)

### 1. リポジトリのクローン
```bash
git clone https://github.com/GenbuHase/Trainfo.git
cd Trainfo
```

### 2. 依存パッケージのインストール
```bash
npm install
```

### 3. 開発サーバーの起動
```bash
npm run dev
```
ブラウザで `http://localhost:5173/` を開くとアプリケーションが起動します。

> [!NOTE]
> **ダークマップについて**: デフォルトではAPIキー不要なOSMダークモードが自動適用されます。CARTO公式のDark Matterタイルを利用したい場合は、`.env` 等で `VITE_CARTO_API_KEY=your_key` を設定してください（[CARTO Basemaps](https://carto.com/basemaps/apikey/) で無料取得可能）。

### 4. ダイヤ・時刻表データの再取得・ビルド（任意）
```bash
# 例: 東急東横線のダイヤをYahoo!から再生成
node scripts/runYahooImporter.cjs --line tokyu_toyoko

# 公式列車番号（trainNumber）のエンリッチメント（例: 東横線）
node scripts/enrich_train_numbers.cjs tokyu_toyoko

# 汎用直通リンカーの実行（全48路線の直通ペアを自動照合・結合）
node scripts/runThroughLinker.cjs
```

### 5. プロダクションビルド＆プレビュー
```bash
npm run build
npm run preview
```

## 🚢 デプロイ (GitHub Pages)

### GitHub Actions による自動デプロイ（推奨）
1. 本リポジトリの **Settings** > **Pages** を開きます。
2. **Build and deployment** の **Source** を **「GitHub Actions」** に設定します。
3. `master` または `main` ブランチにコミットをプッシュすると、自動的にビルド＆デプロイが実行されます。
