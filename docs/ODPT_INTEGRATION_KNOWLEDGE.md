# ODPT（公共交通オープンデータ）の活用知見と将来設計ガイド

本ドキュメントは公共交通オープンデータ協議会（ODPT: Open Data Challenge for Public Transportation）のデータ活用に関する知見、初期実装の経緯と撤去理由、および将来 Trainfo へ再導入・拡張する際の推奨アーキテクチャをまとめた技術資料です。

---

## 1. 歴史的経緯と初期実装の撤去理由

### 初期実装（東武東上線単一路線時代）

Trainfo のプロトタイプ初期に東武東上線専用アプリとして開発されていた際は、クライアントサイド（ブラウザ）から直接 ODPT API へ接続して東武鉄道の運行情報（`odpt:TrainInformation`）を取得するクライアント（`odptApi.ts`）を実装していました。

### 撤去に至った理由

首都圏・北関東・甲信越・東北・東海・近畿・山陽エリアを網羅する24事業者・全174路線の広域マルチ路線マップへ拡張した際、東武鉄道のみ外部APIから取得する構成は全体の整合性を欠いていました。また ODPT API はAPIキー（コンシューマーキー）を必要とするため、GitHub Pages 配信のフロントエンドにキーを埋め込むか利用者に入力させる必要があり、セキュリティおよび導入手順の課題がありました。さらに Trainfo は時刻ジャンプや遅延シミュレーション（定刻 / +5分 / +15分 / ランダム局所遅延）など利用者がダイヤを操作できるシミュレーター設計へ発展したため、運行情報表示もアプリ内のシミュレーション状態と連動する形に改めています。

## 2. ODPTデータのリソース評価と活用可能性

鉄道可視化・シミュレーターアプリにおいて、ODPT から取得できる主要なデータリソースの有用度と活用案を以下に整理します。

| リソース種別 | 有用度 | 活用案 | 主な提供事業者と備考 |
| :--- | :---: | :--- | :--- |
| `odpt:Train`（リアルタイム車両位置） | 高 | フライトレーダー型の在線追跡（実在の営業列車がどの駅間・駅ホームにいるか、実遅延秒数を地図上に反映） | 東京メトロ、都営地下鉄、東急、相鉄、小田急など。更新間隔が30秒〜1分のため、Trainfo の軌道補間（`trackGeometry.ts`）との併用が必要です。 |
| `odpt:StationFacility`（駅施設・構内・バリアフリー） | 中〜高 | 駅詳細パネルの拡充（エレベーター最寄り号車案内、ホームドア設置有無、車椅子対応ルート、改札・出入口番号の表示） | 東京メトロ、都営地下鉄、JR東日本、私鉄各社。静的マスタとしてビルド時に取り込めるため、APIキー不要で安全に実装できます。 |
| `odpt:TrainTimetable`（列車編成・車両マスタ） | 中〜高 | 直通列車の充当車両・編成表示（相鉄・JR直通線における相鉄車 12000系と JR車 E233系7000番台の判定、東急・相鉄直通における東急車 5050系・3020系／相鉄車 20000系・21000系／メトロ車 17000系の判定、10両/8両の編成表示） | 各社。運用・充当情報と連携することで、マップ上の列車アイコンや編成情報を作り分けられます。 |
| `odpt:TrainInformation`（複数社運行情報） | 中 | 首都圏の運転見合わせ・遅延区間の赤色表示や振替輸送ルートの強調表示 | 首都圏各社。クライアント直接接続ではなく、BFF（バックエンド集約）でのキャッシュ配信が前提となります。 |

## 3. 将来導入時の推奨アーキテクチャ

ODPT を再度導入する場合は、以下の2つのアプローチを推奨します。

### アプローチA: 静的取り込み（推奨・導入難易度低）

対象は駅施設データ（`odpt:StationFacility`）、車両編成マスタ、出入口情報など更新頻度の低いデータです。

```text
[ODPT API]
    |
    v (ビルドスクリプト: scripts/ingestOdptFacilities.cjs)
[正規化JSON / stations.ts]
    |
    v (Vite Build)
[静的Webアプリ (GitHub Pages)]
```

この構成では APIキーを公開リポジトリやブラウザに露出させる必要がなく、実行時のAPI障害や通信待ちも発生せず安定して動作します。また GitHub Pages の静的ホスティング構成をそのまま維持できます。

### アプローチB: エッジBFF集約（リアルタイム在線追跡モード）

対象はリアルタイム車両位置（`odpt:Train`）および運行情報（`odpt:TrainInformation`）です。

```text
[ブラウザ / Trainfo]
    |
    v (GET /api/live-trains)
[Cloudflare Workers / Vercel Edge Functions] (BFF)
    |-- APIキー秘匿
    |-- 複数事業者（メトロ・都営・東急等）を並列取得
    |-- 差分正規化と10秒キャッシュ (KV / Cache API)
    +-- レートリミット制御
    |
    v
[ODPT API (各社エンドポイント)]
```

ODPT の在線位置は離散的（「A駅〜B駅間」等）で更新に遅れがあるため、サーバーから受け取った駅間データをもとに Trainfo 側のエンジン（`trainSimulation.ts`）で駅間を滑らかに連続移動させます。また、全路線で時刻操作できるダイヤシミュレーションと、対応路線のみ実時間同期する LIVE 在線モードを UI 上で明確に切り替えられるようにします。

## 4. 規約・ライセンス上の留意点

ODPT のデータを利用する際は、以下の利用規約・ガイドラインを遵守します。

1. アプリケーション内の設定やフッター、モーダル等に、以下の指定文言を明記します。
   > 「本アプリケーションで利用している公共交通データは、公共交通オープンデータセンターにおいて提供されるものです。商用・非商用を問わず、利用者は公共交通事業者各社からの直接のサポートを受けることはできません。」
2. ODPT への過剰な直接リクエストを防ぐため、適切な有効期間（運行情報は1〜2分、在線位置は15〜30秒程度）を設定し、キャッシュを徹底します。
